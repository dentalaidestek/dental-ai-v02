# Fixes following the 20-request live audit — 2026-10-17

These changes extend PR #135. They have not been merged or deployed. No new paid model requests were made while implementing them.

## Cost evidence

The completed live audit recorded 46 Claude calls for 20 scenarios: 20 planning calls and 26 generation calls. The user's later $0.13 dashboard total is not an isolated invoice for these requests. If all $0.13 belonged to them, the arithmetic mean would be $0.0065 per scenario. ChatGPT subscription pricing does not establish an equivalent API cost.

## Changes

| Observed problem | Implemented behavior | Verification |
| --- | --- | --- |
| Grading the last five generated questions scanned 284 chunks, attached 89 pages, and used eight calls | Planner identifies submitted choices semantically. Server grades the latest generated set using its stored key. No retrieval, embedding, original-page materialization or generation for that grade. Planning remains one call. | Controlled provider/retrieval spies forbid these extra operations; five-answer total is calculated locally. |
| Generated questions repeated a fact and exposed the correct option in the stem | Same generation call returns a structured set with five unique choices, a key, explanation, canonical fact and source page. Validate count, choices, selected source references, prior fact/stem repetitions and positive-stem answer exposure before emitting. At most one repair call. | Actual Basion failure reproduced; foreign page/material, malformed keys/options, repeated facts and exhausted repair budget rejected. |
| Grading totals did not sum to the question count | Local per-question comparison computes correct, wrong and blank totals from the stored key. | Five answers produce exactly one correct and four wrong in the regression fixture. |
| Later grading might reuse stale or unrelated keys | Key lives only in server-side source_evidence_json. Restore only from owned history rows matching the full saved answer hash and current source versions. Do not fall back past a newer unkeyed question set. Old messages without keys receive an explicit explanation instead of a whole-course scan. | Hash, index change, malformed metadata, legacy data and newer-set regressions. |
| Small complete text batches were summarized before final generation | A single complete text batch goes directly to generation, preserving its original evidence and returning the generated key to the parent retrieval. | One provider invocation in a controlled single-batch test; previous intermediate extraction removed. |
| Event document explicitly excluded by the user was still read | Planner receives a bounded owned filename manifest and can positively select remaining files before content retrieval. Existing owned/versioned source-file filters enforce selection. | Existing source-boundary tests plus unchanged SQL ownership checks; semantic exclusion quality requires the next live retest. |
| Topic-frequency labels split related concepts into inconsistent groups | Planner selects a common vocabulary from actual indexed headings for all inventory batches. Server normalizes to this vocabulary; unmatched labels are counted separately and excluded from rankings. An unavailable vocabulary yields unclassified records instead of a fabricated topic ranking. | Inventory regression retains unmatched questions and reports that the ranking is incomplete. Broad heading quality still requires source review. |
| Native-page replacement erased inherited headings; correct section answer included speculative caveats | Native evidence retains matched section paths. Fully selected named sections carry separate completeness metadata without claiming the entire course was supplied. | Native-page tests and real-source SQL matrix. |
| Valid planner text was rejected under a 300-character clarification limit | Explicit 1200-character clarification contract, short-response prompt, and fixed field-specific diagnostics. NUL, wrong types and oversized text still fail validation. | Valid 300–1200 character clarification succeeds; 1201 characters fails. The live raw planner output was not retained, so the exact original invalid field is not proven. |

Generated keys and rationales are model outputs grounded in the selected sources, not independent human-certified answer keys. Structural checks cannot prove every clinical claim, semantic novelty, single-answer validity or difficulty. The next live retest must review these against the original notes. Legacy sets do not acquire invented keys.

## Validation

- Main local suite: **811 passed, 34 skipped, 30 deselected, 576 subtests passed**. Benchmark/holdout/combined tests were deliberately deselected; PostgreSQL-dependent tests are skipped without a database URL.
- Real-source SQL matching matrix: **20 cases passed** (one parametrized workflow test) using the existing uploaded-note fixture on PGlite/PostgreSQL-compatible SQL. This is not a live model accuracy score or a full native PostgreSQL suite.
- Focused quiz, question-output and exam-inventory suite: **43 passed**.
- Python compilation and git whitespace checks passed.
- Existing GitHub Actions runs failed before steps; this implementation does not claim remote CI or production validation.

## Retest after approval and deployment

Repeat the original 20 scenarios with the same course/source versions and record planner/generation counts, attachments, input/output tokens, source matches, time to visible answer and total duration. In particular: two consecutive distinct five-question sets; grade A/B/C/D/E against the latest saved set; long patient-data clarification; file exclusion; common-granularity topic frequency; twenty hard questions with plausible distractors. Compare actual usage rather than estimating savings from dashboard balance deltas. A two-request concurrency test does not establish 60,000-user capacity.
