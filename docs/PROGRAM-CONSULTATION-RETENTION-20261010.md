# Program consistency and consultation retention

The dashboard now queries the current Istanbul calendar day instead of the next 90 days. Weekly occurrences use the same expansion helper as Program. The Today tab resets to the actual current day. Day/week arrows and horizontal swipe navigation are available. Navigation requests render only the program fragment, cancel superseded requests, ignore late responses, and cache up to 12 views; mutations and realtime updates invalidate the cache. Calendar SQL excludes historical one-off events that cannot overlap the requested range.

Only ACTIVE and WAITING_START consume expert capacity. EXPERT_COMPLETED and DISPUTE release it immediately. Legacy capacity-auto-busy profiles are reconciled during startup. Acceptance, proposal acceptance, and continuation serialize on the expert profile and recheck the five-case ceiling before acquiring a slot.

Retention begins at final completion, including the actual 24-hour confirmation deadline for delayed automatic completion. The requester may report a completed consultation through day 3 inclusive. Unreported conversations are purged at day 7 through the existing durable deadline queue, with no new cron. Existing completed conversations with a completion timestamp are backfilled at startup. Any historical report, dispute, or linked support ticket prevents automatic deletion, including resolved reports.

Deletion removes chat message rows, reply/annotation content, durable message previews/push-delivery references and shared-media links, while retaining the consultation/business/audit record and patient originals. Chat-owned attachment references enter a committed deletion outbox and are removed by a subsequent durable job, so failed database transactions cannot prematurely delete files. Attachment failures use the existing queue retries and failure logs. Only administrators can request permanent deletion of protected conversations. Tombstones and row locks prevent HTTP, WebSocket, media and annotation writes after deletion; participants receive a deletion event. Manual user deletion only hides that user's inbox state, with existing seven-day undo, and opening a room no longer silently undoes it.

Validation at authoring: 56 focused application tests passed. Rendered Program and consultation-room inline JavaScript passed Node syntax checks. New PostgreSQL tests cover concurrent idempotent purge and report-versus-purge serialization; these require the PostgreSQL CI job. Full regression results and CI status should be checked on the published commit. No deployment or production data deletion was performed.
